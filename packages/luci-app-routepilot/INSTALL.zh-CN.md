# RoutePilot 0.2.24 安装与恢复

当前包版本为 **0.2.24-4**。完整包面向 **ARM64 / OpenWrt 24.10**，现场验证机为 GL.iNet GL-MT6000。不是路由器固件，不能用“刷写固件”上传；其他架构和机型没有验收。

## GitHub 公开版与完整安装包的区别

GitHub 公开版提供源码、`luci-app-routepilot_0.2.24-4_all.ipk` 和 `SHA256SUMS`。它**不是开箱即用的完整首次安装包**，不包含 Cloudflare 客户端或 ARM64 Debian 运行环境。

- 已有兼容 RoutePilot 运行环境的设备：备份后，在维护窗口用 `opkg install ./luci-app-routepilot_0.2.24-4_all.ipk` 更新插件；保留原运行环境和注册信息。
- 全新设备：还须按第三方许可自行准备未注册运行环境及固件匹配依赖。只有 IPK 不能完成首次安装；本仓库没有提供通用运行环境生成器。
- 下文 `install-router.sh` 属于完整包安装流程，依赖同目录的运行环境与校验文件；不能拿公开源码目录直接运行。

## 完整包流程（仅适用于自行合法准备齐文件的安装目录）

- `luci-app-routepilot_0.2.24-4_all.ipk`：与本次已安装版本相同的插件。
- `routepilot-runtime-arm64_2026.8.2115.0.tgz`：未注册的 WARP 运行环境，供自己的兼容设备首次安装。
- `install-router.sh`：校验 / 首次安装 / 明确升级三个模式。
- 源码 ZIP、设置说明、许可证、运行环境来源记录及 `SHA256SUMS`。

完整包不包含路由器密码、WARP 注册身份、Cloudflare API 令牌、私人节点链接或现有设备 / 分流配置。新路由器仍需要自己的 Cloudflare 账户授权。完整包流程要求自行准备运行环境；与固件绑定的系统依赖及缺少的 `xray-core` 从该路由器自己的匹配软件源安装，**不是完全离线的依赖全集**。

## 首次安装

建议至少 1 GB 内存、500 MB 可用存储，先准备可恢复的路由器管理入口。不要在 Mac / Windows 上运行路由器安装脚本。

1. 解压完整 ZIP，将其中同一个安装目录完整放到路由器，勿混入旧版 IPK。
2. 在路由器管理员 shell 进入该目录，先运行 `sh install-router.sh --check`。它只核对平台、文件与空间，不安装、不改变线路。
3. 确认首次安装后运行 `sh install-router.sh --install`。需要可用网络访问当前固件的软件源；脚本不强制绕过依赖，不升级固件，也不会覆盖已有运行环境。
4. 打开 LuCI → 服务 → RoutePilot → Cloudflare 配置中心。首次安装默认关闭；登录自己的组织 / 账户，读取出口，选择设备或 LAN 范围，保存后再手动启用。
5. Workers 备用在第五组配置。上方节点列表显示创建记录及已保存节点；创建 / 绑定、保存为备用和手动启用分别反馈，备用需要独立检测后才能手动启用。

安装不是跨步骤事务。依赖失败时先核对软件源和内核版本；运行环境解压完成后 IPK 失败时，目录会保留，不要删除注册目录后盲目重试。只删除脚本自己尚未提交的临时解压目录。

## 已有设备更新

已经运行本版的设备无需重复安装。

其他已有兼容设备可以使用 `sh install-router.sh --upgrade`，或仅安装核对过的本版 IPK。升级保留现有注册环境和配置；普通 opkg 升级可能短暂重连，并按原有开关恢复，不能把“首次安装默认关闭”理解成所有升级都会关闭。

先保存旧 IPK、版本 / 哈希及必要的私人备份，再选择维护窗口。私人备份不要发布到 GitHub。包内运行环境只用于首次安装，升级不能覆盖已有 `/opt/routepilot/runtime`。

## 恢复与迁移

需要退出接管时，先在总览手动关闭，等待实际清理确认，再核对终端网络。管理连接异常时使用预先准备的恢复入口，勿连续尝试部署或切换协议。

恢复旧插件前核对其配置和规则目录兼容性；卸载不会自动删除 WARP 运行环境和注册信息。普通配置导出只含本插件设置，排除登录、API 令牌和私人节点；导入后默认关闭，新设备需重新授权。

## 当前验证边界

插件在既有 GL-MT6000 上已核对安装文件、当前主线路与配置保留；本次进度反馈通过本地隔离回归和真机只读检查。没有为了打包在另一台全新路由器上重新执行完整首次安装，也没有据此宣称所有机型、长期稳定性或 WireGuard 协议已验收。Workers 仅代理 IPv4 TCP；主线路与 IPv6 处理以自己的分流设置为准。
